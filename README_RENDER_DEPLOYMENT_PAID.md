# Render Deployment Guide (Paid Tier)

This guide covers deploying the Marketing Post Scheduler to Render's paid tier for production use with optimal performance and reliability.

## Prerequisites

Before deploying, ensure you have:

1. **Render Account**: [Create account](https://render.com) with paid plan
2. **MongoDB Atlas**: Database connection details
   - Username and password
   - Cluster address
   - Application name
3. **Cloudinary Account**: Image storage credentials
   - Cloud name
   - API key
   - API secret
4. **OpenAI API Key** (optional): For AI content generation features

> Developer note: For local development with frontend and backend auto-reload (nodemon), run:
> 
> ```bash
> just start-dev
> ```
> This uses the dev compose override to run the frontend and backend with nodemon. Normal `just start` remains available.

## Deployment Steps

### 1. Repository Setup

Ensure your code is in a Git repository accessible to Render (GitHub, GitLab, etc.).

### 2. Create Blueprint Instance

1. Log in to your Render dashboard
2. Click **"New"** → **"Blueprint"**
3. Connect your repository
4. Render will detect `render.yaml` and create services automatically

### 3. Configure Environment Variables

Set these environment variables in your **backend service**:

#### Required Variables

```env
# Database
MONGO_USERNAME=your_atlas_username
MONGO_PASSWORD=your_atlas_password
MONGO_CLUSTER=your_cluster.mongodb.net
MONGO_APP_NAME=your_app_name
NODE_ENV=production

# Image Storage
CLOUDINARY_CLOUD_NAME=your_cloud_name
CLOUDINARY_API_KEY=your_api_key
CLOUDINARY_API_SECRET=your_api_secret

# AI Features (optional)
OPENAI_API_KEY=your_openai_key
```

#### Auto-Generated Variables

- `JWT_SECRET`: Automatically generated by Render
- `FRONTEND_URL`: Set automatically based on frontend service URL

### 4. MongoDB Atlas Configuration

1. **Network Access**: Add Render's IP ranges to MongoDB Atlas IP allowlist
   - Go to Network Access in MongoDB Atlas
   - Add IP Address: `0.0.0.0/0` (allows all IPs) or specific Render IPs
2. **Database User**: Ensure your database user has read/write permissions
3. **Connection String**: Verify your cluster address is correct

### 5. Deploy Services

1. Navigate to your backend service in Render dashboard
2. Click **"Manual Deploy"** → **"Deploy latest commit"**
3. Monitor build and deployment logs
4. Repeat for frontend service if needed

### 6. Verify Deployment

After successful deployment:

- **Frontend URL**: Provided by Render for frontend service
- **Backend API**: Provided by Render for backend service
- **Health Check**: Visit `https://your-backend-url.onrender.com/api/health`

## Production Optimizations

### Performance Benefits (Paid Tier)

- **No Cold Starts**: Services stay active continuously
- **Better Resources**: More CPU and memory allocation
- **Faster Build Times**: Priority build queue access
- **Custom Domains**: Use your own domain names
- **SSL Certificates**: Automatic HTTPS with custom domains

### Monitoring and Scaling

1. **Service Metrics**: Monitor CPU, memory, and response times
2. **Auto-Scaling**: Configure based on traffic patterns
3. **Log Retention**: Extended log history for debugging
4. **Alerts**: Set up notifications for service issues

### Security Considerations

1. **Environment Variables**: Never commit secrets to repository
2. **CORS Configuration**: Restrict to your frontend domain
3. **Rate Limiting**: Implement API rate limiting
4. **Database Security**: Use strong passwords and IP restrictions

## Troubleshooting

### Build Issues

- Check build logs in Render dashboard
- Verify all dependencies in `package.json`
- Ensure Node.js version compatibility

### Runtime Errors

- Monitor service logs for error details
- Verify environment variables are set correctly
- Check MongoDB Atlas connection and permissions

### Performance Issues

- Monitor service metrics in Render dashboard
- Consider upgrading service plan if needed
- Optimize database queries and API calls

### Database Connection

- Verify MongoDB Atlas IP allowlist includes Render IPs
- Test connection string format
- Check database user permissions

## Maintenance

### Regular Updates
